# AgroDala

Интернет-магазин сельскохозяйственного инструмента: категории по назначению с иконками на главной
странице, раскрывающийся блок фильтров и сортировки, градация цен, личный кабинет, корзина и
административная панель. Все товары, покупатели и заказы хранятся в Cloud Firestore.

Учебный проект по дисциплине «Алгоритмы и структуры данных» (КАТИУ им. С. Сейфуллина,
группа КИ СОПР 06-057-25-22). Автор — Титов Е. И.

**Опубликованная версия: https://agrodala.artmori.art** (запасной адрес — https://agrodala.web.app; каталог, вход, кабинет и админ-панель работают
всегда; оформление заказа, смена статусов, импорт и загрузка фото — когда запущен сервер на ноутбуке
разработчика, см. [«Публикация»](#публикация)). [Инструкция пользователя](docs/user-guide.md).

## Технологии

| Часть | Что используется |
|---|---|
| Клиент | HTML5, CSS3, JavaScript (ES-модули) без фреймворков и сборщика |
| База данных | Cloud Firestore |
| Вход и регистрация | Firebase Authentication |
| Фотографии товаров | Cloud Storage for Firebase |
| Серверные операции | Cloud Functions на Node.js 22 (расчёт суммы заказа, статусы, импорт CSV, фото) |
| Разработка и тесты | Firebase Local Emulator Suite, Vitest, `@firebase/rules-unit-testing`, Playwright |
| Хостинг | Firebase Hosting (по ТЗ планировался PS.kz — см. [«Публикация»](#публикация)) |

Сайт работает без собственного сервера: браузер напрямую обращается к Firebase, а всё, что нельзя
доверять браузеру, проверяют правила безопасности и Cloud Functions.

## Запуск на своём компьютере

Нужны **Node.js 22+** и **Java 21+** (на Java работают эмуляторы Firebase). Аккаунт Google и
настоящий проект Firebase не нужны: всё работает в локальных эмуляторах с проектом
`demo-agrodala`.

```sh
npm install        # один раз (зависимости Cloud Functions ставятся сами, в functions/)
npm start          # тесты → тестовые данные → сайт и эмуляторы; остановить — Ctrl+C
```

После запуска в терминале появятся адреса:

- сайт — http://127.0.0.1:28571
- панель эмуляторов (данные базы, пользователи, фото) — http://127.0.0.1:28572

`npm start` сначала прогоняет тесты базы, правил, каталога и Cloud Functions (около минуты), потом заполняет базу
тестовыми данными и держит сайт запущенным. Если тесты упали, сайт всё равно запустится, а в конце
будет написано «ЕСТЬ ОШИБКИ».

Отдельные команды, если нужно по частям:

```sh
npm run dev        # только эмуляторы (база пустая)
npm run seed       # в другом терминале: заполнить базу
npm test           # только тесты
```

Открыть сайт на настоящем телефоне (телефон и компьютер в одной сети Wi-Fi или в Tailscale):

```sh
npm run start:phone  # то же, что npm start, но эмуляторы доступны из сети (firebase.phone.json)
hostname -I          # адрес компьютера, на телефоне открыть http://<адрес>:28571
```

В этом режиме эмуляторы доступны всем в сети, поэтому он только для проверки на время работы:
там лежат только тестовые данные, но и правами администратора эмулятора может пользоваться любой.

Порты эмуляторов — 28571–28579, они заданы в `firebase.json` (и такие же в `firebase.phone.json`).
Номера выбраны редкими, чтобы не мешать другим программам. Если какой-то всё же занят (узнать чем:
`ss -ltnp | grep 2857` в Linux, `netstat -ano | findstr 2857` в Windows), поменяйте его в
`firebase.json`, `firebase.phone.json` и `public/js/firebase.js` — `npm test` проверит, что номера
совпадают.

Тестовые учётные записи (пароль у всех `agrodala123`):

| Почта | Роль |
|---|---|
| `admin@agrodala.example` | администратор |
| `manager@agrodala.example` | менеджер по продажам |
| `content@agrodala.example` | контент-менеджер |
| `buyer@agrodala.example` | покупатель: 5 заказов, корзина из 3 товаров |
| `farmer@agrodala.example` | покупатель: 3 заказа, корзина из 1 товара |

Сценарий покупки для проверки: войти как `farmer@…` → корзина → «Оформить заказ» → в кабинете
появится новый заказ. Затем войти как `manager@…` → «Админка» → «Заказы» → номер заказа →
«Подтвердить». Журнал Cloud Functions — в панели эмуляторов, вкладка Logs.

## Публикация

Опубликованный сайт — https://agrodala.artmori.art (он же https://agrodala.web.app; поддомен подключён в Hosting → Custom domains записью CNAME в Cloudflare, без проксирования), проект Firebase `agrodala` (алиас `prod` в `.firebaserc`).
У проекта тариф Spark (бесплатный): на нём работают Cloud Firestore, Authentication и Hosting, а Cloud
Functions и Cloud Storage требуют тарифа Blaze с привязанной картой. Поэтому сейчас система разделена:

| Где | Что |
|---|---|
| Облако Firebase | сайт (Hosting), база (Firestore, europe-central2), вход (Authentication), фото товаров из тестовых данных — публикуются вместе с сайтом |
| Ноутбук разработчика, `npm run backend` | Cloud Functions в эмуляторе, но с настоящей базой и пользователями: заказы, статусы, импорт CSV; загруженные в админ-панели фото (эмулятор Storage, наружу не открыт — фото выдаёт функция `photo`) |

Функции доступны из интернета через Cloudflare Tunnel ноутбука: `https://agrodala-api.artmori.art`,
наружу открыт только путь `/agrodala/europe-central2/…` (адрес задан в `public/js/firebase.js`).
Эмулятор функций не проверяет подпись токена входа, поэтому в этом режиме её проверяют сами функции
(`functions/index.js`, `verifiedAuth`). Когда ноутбук выключен, каталог, вход, кабинет и админ-панель
работают, а оформить заказ, сменить статус, импортировать CSV и загрузить фото нельзя — сайт пишет,
что сервер магазина недоступен.

Команды (нужен вход в Firebase CLI: `npx firebase login`):

```sh
npm run backend        # сервер на ноутбуке; остановить — Ctrl+C (загруженные фото сохранятся в .emulator-data/backend)
npm run deploy:site    # опубликовать сайт (фото из seed/images копируются в public/img/products/ автоматически)
npx firebase deploy -P prod --only firestore   # правила и индексы базы
npm run seed:prod      # заполнить облачную базу; если в ней уже есть товары — только с -- --reset
npm run check:indexes  # хватает ли индексов облачной базе: 204 запроса каталога (эмулятор индексы не проверяет)
```

`npm run backend` и `seed:prod` берут ключ сервисного аккаунта из `~/.config/agrodala/service-account.json`
(консоль Firebase → Настройки проекта → Сервисные аккаунты; в репозиторий не попадает). Пароль
демонстрационных учётных записей в облаке — не `agrodala123`, а случайный: `seed:prod` создаёт его
в `~/.config/agrodala/prod-password`. Туннель настраивается один раз: в `~/.cloudflared/config.yml`
перед последним правилом —

```yaml
  - hostname: agrodala-api.artmori.art
    path: ^/agrodala/europe-central2/
    service: http://127.0.0.1:28579
```

затем `cloudflared tunnel route dns <туннель> agrodala-api.artmori.art` и перезапуск cloudflared.
(Tailscale Funnel для этого не подходит: на компьютерах из той же сети Tailscale его адрес указывает
на внутренний адрес 100.x, и Chrome не пускает к нему запросы публичного сайта.)

`npm start` (локальная копия с эмуляторами) и `npm run backend` занимают одни порты, одновременно не запускаются.

**Переход на Blaze.** Подключить тариф в консоли, создать хранилище (Storage, europe-central2),
в `public/js/firebase.js` поставить `LAPTOP_BACKEND = null`, затем `npm run deploy` — правила, индексы,
функции и сайт. Код функций и сайта менять не нужно.

## Тесты

Сначала остановите `npm start` или `npm run dev`: тесты сами поднимают эмуляторы и заполняют базу.

```sh
npm test               # тестовые данные, правила Firestore и Storage, запросы каталога, индексы, Cloud Functions
npm run test:ui        # браузер: адаптивность, навигация, вход, каталог, покупка (Chromium, компьютер и телефон)
npm run test:browsers  # те же сценарии в Firefox и WebKit (движок Safari)
npm run screenshots    # переснять docs/screenshots
```

Браузеры для `test:ui` и `test:browsers` устанавливаются один раз: `npx playwright install chromium firefox webkit`.
